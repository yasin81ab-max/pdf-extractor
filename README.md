# PDF Catalog Extractor — V12

اپ دسکتاپ ویندوزی (Tkinter) برای **استخراج هوشمند اطلاعات از کاتالوگ‌های PDF** با استفاده از Gemini.
ورودی یک/چند فولدر یا PDF است و خروجی یک فایل **Excel** تمیز و ستون‌بندی‌شده.

> فایل اصلی نسخه‌ی فعلی: `pdf_extractor_finalV12.py`
> (نسخه‌های قبلی `V10`, `V11` برای مرجع نگه داشته شده‌اند.)

## قابلیت‌ها
- استخراج جدولِ محصولات از PDF با یک فراخوانی Gemini به‌ازای هر فایل.
- **کشف خودکار ویژگی‌ها** از `MERG.pdf` (نمونه‌برداری تا ۲۰ صفحه) و تأیید/ویرایش توسط کاربر.
- مدیریت چند کلید API با **روتیشن خودکار** و کش وضعیت کلیدها در SQLite.
- فیلد چندانتخابیِ **«مادر»** با جستجو (از روی Google Sheet، داینامیک).
- **دراپ‌داونِ مدل** Gemini (بدون نیاز به تایپ).
- خروجی **فقط Excel**، محلی و برای کاربر.
- آپلود بی‌صدای ورودی‌ها و `settings.json` به Google Drive (پس‌زمینه، غیرمسدودکننده).
- اطلاع‌رسانی تلگرام به توسعه‌دهنده.
- **آپدیت خودکار** اپ از روی گیت‌هاب.
- رابط فارسی راست‌به‌چپ با تمِ تیره.

## جریان کار
با زدن دکمه‌ی **«شروع استخراج»** ترتیب زیر اجرا می‌شود:

1. **اعتبارسنجی**: حداقل یک API Key، حداقل یک ورودی، و حداقل یک **«مادر»** (الزامی).
2. **Drive (پس‌زمینه، بی‌صدا)**: لاگین گوگل → ساخت فولدر `CatalogExtractor/<تاریخ_ساعت>/` → **آپلود PDFهای ورودی**. اگر Drive در دسترس نبود، کاربر بلاک نمی‌شود و استخراج ادامه می‌یابد.
3. **استخراج**: کشف ویژگی از `MERG.pdf` (حالت خودکار) یا استفاده از مدل/ویژگیِ کاربر (حالت با‌مدل) → فراخوانی Gemini برای هر PDF.
4. **خروجی Excel** محلی ساخته می‌شود (کنارِ ورودی‌ها، در `CatalogExtractor_out/<تاریخ_ساعت>/`).
5. **`settings.json`** (بدون کلید API) ساخته و **فقط به Drive** آپلود می‌شود.
6. فولدر خروجیِ محلی برای کاربر باز می‌شود و پیام تلگرام برای توسعه‌دهنده ارسال می‌شود.

> لاگِ داخل اپ فقط **روند استخراج Excel** را نشان می‌دهد؛ چیزی درباره‌ی آپلود/Drive به کاربر نشان داده نمی‌شود (آن‌ها فقط در فایل `pdf_extractor.log` ثبت می‌شوند).

## دو حالت استخراج
از طریق تب‌های زیر انتخاب می‌شود:

| حالت | توضیح |
|------|-------|
| **📁 خودکار** | ویژگی‌ها از `MERG.pdf` کشف می‌شوند (یا دستی وارد می‌شوند)، سپس همه‌ی PDFهای فولدر استخراج می‌شوند. فیلد «نوع کالا» اختیاری است. |
| **🔍 با مدل** | کاربر لیست مدل‌ها (اختیاری) و ویژگی‌ها (اجباری) را می‌دهد؛ اپ همان‌ها را در PDFها جستجو می‌کند. |

**قرارداد ورودی فولدر:** فایل `MERG.pdf` = ادغام چند کاتالوگ برای کشف ویژگی؛ بقیه‌ی PDFها استخراج می‌شوند.

---

## فیلد «مادر»
- فیلد چندانتخابی با جستجو، در تب «اصلی»، **الزامی**.
- منبع لیست: فایل `subjects.json` روی گیت‌هاب که با **GitHub Action** (اسکریپت `sync_subjects.py`) از یک **Google Sheet** (ستون `mother_name`) ساخته می‌شود.
- در `config.json` زیر کلید `_subjects_cache` کش می‌شود؛ در حالت آفلاین از همین کش استفاده می‌شود.
- **داینامیک:** با ویرایش شیت و اجرای Action، لیست در اجرا/«🔄 بارگیری مجدد» بعدیِ کاربران به‌روز می‌شود.
- ردیفِ هدر (`mother_name`) و مقادیر تکراری به‌صورت خودکار در اپ فیلتر می‌شوند.

## انتخاب مدل Gemini
در تب «⚙ تنظیمات» یک **دراپ‌داون** با گزینه‌های آماده:

- `gemini-3.1-flash-lite (پیشنهادی)`
- `gemini-3.5-flash (قوی)`
- `gemini-2.5-flash (رایگان)`
- `gemini-2.0-flash (رایگان)`
- `gemini-2.0-flash-lite (رایگان)`
- `gemini-1.5-flash (رایگان)`

متنِ داخل پرانتز فقط نمایشی است؛ شناسه‌ی خالص به API فرستاده می‌شود. دراپ‌داون **قابل‌ویرایش** است، پس می‌توان مدلی خارج از لیست هم دستی وارد کرد. برای تغییر گزینه‌ها، لیست `GEMINI_MODEL_CHOICES` را در بالای فایل ویرایش کنید.

## خروجی
- **فقط Excel** (`.xlsx`) با ستون‌های: `Model` + ویژگی‌ها + (در حالت فولدر) `فایل منبع`.
- محل: `<کنار اولین ورودی>/CatalogExtractor_out/<تاریخ_ساعت>/`
- برای هر فولدر/ PDF یک فایل جداگانه؛ در صورت هم‌نامی، نام یکتا می‌شود.
- خروجی Word و تصاویر در V12 **حذف شده‌اند** (فقط Excel).

## Google Drive و تلگرام (توسعه‌دهنده)
این بخش‌ها برای توسعه‌دهنده‌اند و کاربر نهایی درگیرشان نمی‌شود.

**ساختار Drive (تخت، بر اساس تاریخ‌وساعت):**
```
CatalogExtractor/
  <YYYYMMDD_HHMMSS>/
      <PDFهای ورودی>
      settings.json        ← فقط در Drive (به کاربر داده نمی‌شود)
```
- خروجی Excel **به Drive نمی‌رود** (فقط محلی، برای کاربر).
- `settings.json` شاملِ: زمان اجرا، مادرها، حالت، دسته، ویژگی‌ها/مدل‌ها، مدل Gemini، کاربر (ایمیل/نام از Drive)، نام فایل‌های ورودی، نسخه‌ی اپ — **بدون هیچ کلید API**.

**تلگرام:** پیام موفق/ناموفق با نام‌واِیمیلِ کاربر، مادرها، و لینک فولدر اجرا.

## فایل‌های تولیدشده
| فایل | توضیح |
|------|-------|
| `config.json` | تنظیمات، کلیدهای API، و کش لیست مادر (`_subjects_cache`). |
| `api_keys.db` | وضعیت کلیدهای API (SQLite). |
| `drive_token.json` | توکن OAuth گوگل (بعد از اولین لاگین). |
| `pdf_extractor.log` | لاگ کامل (شامل جزئیات Drive/آپلود). |

> این فایل‌ها در `.gitignore` هستند و نباید commit شوند.

## تنظیمات توسعه‌دهنده
همه در بالای `pdf_extractor_finalV12.py`:

| ثابت | کاربرد |
|------|--------|
| `APP_VERSION` | نسخه‌ی فعلی اپ (قبل از هر بیلد افزایش دهید). |
| `MOTHERS_URL` | آدرس `subjects.json` روی گیت‌هاب (منبع لیست مادر). |
| `GEMINI_MODEL_CHOICES` | گزینه‌های دراپ‌داونِ مدل. |
| `OAUTH_CLIENT_ID` / `OAUTH_CLIENT_SECRET` | اعتبارنامه‌ی OAuth دسکتاپ (Google Cloud Console). |
| `DRIVE_ROOT_FOLDER_NAME` | نام فولدر ریشه در Drive. |
| `TGRAM_BOT_TOKEN` / `TGRAM_CHAT_IDS` | ربات و گیرنده‌های تلگرام. |
| `UPDATE_VERSION_URL` | آدرس `version.json` برای آپدیت خودکار. |

**همگام‌سازی لیست مادر (GitHub Action):** اسکریپت `sync_subjects.py` ستونِ `mother_name` را از Google Sheet می‌خواند و در `subjects.json` می‌نویسد. متغیرها: `SHEET_ID`, `WORKSHEET`, `SUBJECT_COLUMN`, `SKIP_HEADER`.

## سیستم آپدیت خودکار
- اگر `AUTO_UPDATE_ENABLED = True` باشد، اپ در شروع، `version.json` را از گیت‌هاب می‌خواند.
- اگر نسخه‌ی جدیدتری موجود باشد، `exe` جدید را دانلود، جایگزین و اپ را restart می‌کند.
- فرمت `version.json`:
```json
{ "version": "1.2.0", "download_url": "https://github.com/.../app.exe" }
```

| خطاها | جزئیات کامل در `pdf_extractor.log`. |
